# Stock AI 用户使用手册

> A 股研究与人工确认交易工作台。它用于验证决策流程和前瞻证据，不是自动实盘交易系统，也不构成投资建议。

## 1. 先理解系统边界

当前版本的主流程是：

```text
股池
  ↓
冻结行情/新闻事实快照
  ↓
多个 LLM 独立判断
  ↓
唯一官方 ensemble 合议
  ↓
候选交易计划
  ↓
信息门禁 + 价格门禁 + 资金风控
  ↓
人工确认执行票据
```

独立 LLM 是判断顾问，不拥有资金；只有数据库中唯一标记且已启用的官方 `ensemble` 才有模拟资金账户和持仓。系统当前的执行模式固定为“人工票据”，不会自动连接真实券商下单。

## 2. 启动与首次配置

### Docker 部署

```bash
cp .env.example .env
# 在 .env 或网页“设置”中配置 LLM_API_KEY；行情需要 FUYAO_API_KEY
docker compose up -d
```

默认访问 `http://127.0.0.1:8000`。Docker 使用 `/data/stock_ai.db` 保存应用数据库；Ubuntu 部署通常把它挂载到 `/var/lib/stock-ai/data/stock_ai.db`。

### 本地开发

```powershell
cd backend
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

另开终端启动前端：

```powershell
cd frontend
npm ci
npm run dev
```

本地前端默认是 `http://127.0.0.1:5173`，通过 Vite 代理访问后端 `/api`。

首次启动会自动创建数据库表，并在至少有两个 LLM 时创建默认的“三模合议”官方策略账户。

## 3. 首页“战报”怎么看

首页按顺序回答四个问题：

1. 样本是否足够：账本平仓笔数和权益快照天数是否达到门槛。
2. 官方策略表现如何：资产、收益率、持仓数量和最大回撤。
3. 当前持仓是什么：现金、成本、现价、市值和浮动盈亏。
4. 相对市场如何：官方策略收益曲线与沪深 300 对照。

“平仓”指卖出全部或部分已经买入的持仓，结束一笔交易。平仓后盈亏才成为已实现盈亏；没有卖出时显示的是浮动盈亏。

“账本平仓 12/100”不是今天卖了 12 次，而是账本中已有 12 笔完成平仓的样本，系统要求至少 100 笔才进入样本评估。交易日门槛同理，必须同时满足“天数”和“平仓笔数”两个条件。

首页的“真实资金未就绪”是预期状态：正式公告源、真实券商执行、身份认证、自动 shadow 前瞻证据和足量验证样本尚未全部完成。

## 4. 其他页面

### 策略

查看当前启用的策略板、官方 ensemble 状态、历史规则/研究策略的只读信息，以及因子快照。已退役或历史模型不会重新获得资金授权。

### 研究

用于“理论 → 结构化规格 → 回测 → 人工确认晋升/废弃”。回测实验会冻结代码、配置、数据、股池和截止时间指纹；development 与 holdout 分开，不能用可编辑的旧结果冒充新证据。

### 股池

维护本轮允许 AI 分析的股票。可手动添加，也可在配置 LLM 后触发 AI 选股。股池为空时，顶部“生成候选计划”会先引导你到这里。

### 决策

查看每次运行的进度、模型输出、最终决策、失败原因和证据链。运行中可查看过程，也可以协作式停止；已经写入的记录不会被回滚。

### 计划与票据

候选计划必须通过信息、价格和资金门禁，之后才可能生成待人工确认的执行票据。生成票据不等于成交，系统也不会自动替你下单。

### 模型与策略

管理 LLM 顾问、成员和唯一官方 ensemble。多个 ensemble 无法唯一判定时，系统会失败关闭，不会猜测哪个账户应该接收资金。

### 设置

配置密钥、数据源、调度、股池上限、交易费用和风控参数。密钥只显示脱敏值。代码拥有的资金契约和实盘就绪条件不能通过网页覆盖。

## 5. 一次正常运行

```text
1. 配置 LLM / 扶摇 Key
2. 在“股池”准备标的
3. 在“模型与策略”确认至少一个 LLM 和唯一官方 ensemble
4. 点击“生成候选计划”
5. 在“决策”查看冻结快照和模型过程
6. 在“计划与票据”检查信息/价格/资金门禁
7. 人工确认票据后，才允许进入模拟撮合
8. 回到首页观察持仓、账本样本和收益曲线
```

## 6. 全新开始：清空应用数据

如果确认旧数据不再需要，并且 EMT 是全新的模拟账户，可以重建应用数据库。建议只删除应用数据库，不删除 EMT 桥接目录。

Ubuntu 部署提供了安全脚本：

```bash
cd /opt/stock-ai
docker compose stop stock-ai

# 默认只预览，不删除
./deploy/reset-stock-ai-data.sh

# 确认目标是 /var/lib/stock-ai/data/stock_ai.db 后执行
./deploy/reset-stock-ai-data.sh --yes

docker compose up -d stock-ai
```

脚本只删除 `stock_ai.db` 及其 `-wal`、`-shm`、`-journal` 文件，绝不触碰 `/var/lib/stock-ai/broker`。服务重新启动时，`init_db()` 会创建全新表结构和默认官方策略账户。

重置后首页应从以下状态开始：

```text
账本平仓：0 / 100
交易日：0 / 60
样本状态：不足
执行模式：人工票据
持仓：空
收益曲线：暂无快照
```

注意：如果密钥只写在数据库的“设置”覆盖层中，删除数据库后这些覆盖也会消失；如果密钥写在服务器 `.env`，则会在新库启动后继续生效。建议重置前确认密钥来源。

## 7. 风险与验证

- 模拟撮合不等同于真实券商成交。
- 行情或公告数据不新鲜时，门禁应失败关闭。
- 历史回测不能证明未来盈利；至少要积累足量、不可回看的前瞻样本。
- 不要把“候选计划”“执行票据”理解为已经成交。
- 不要把首页的收益曲线当成实时券商资产证明。

详细部署和实盘前阻断条件见项目根目录 `README.md` 与 `deploy/UBUNTU.md`。
